# Merchant Payout App

A merchant can see available and pending balances, browse activity with cursor pagination, and send a payout to an IBAN. Payouts over 1,000.00 in the selected currency require a native biometric check, and the payout screen warns when a screenshot is taken.

## Run the app

Requirements: Node 22 or newer (the starter `.nvmrc` says 24) and npm. From this directory:

```bash
npm install
npm test
npm run lint
npx tsc --noEmit
```

`npm test` runs Jest with the React Native Testing Library. The suite is 52 tests. `npm run lint` is `expo lint`.

Start the JavaScript bundle:

```bash
npx expo start
```

A browser preview, with the same MSW handlers behind a service worker:

```bash
npx expo start --web
```

The web preview has no Face ID or fingerprint sensor. For a payout over 1,000.00 it asks you to confirm or cancel in a browser dialog so the gate can still be exercised. Screenshot detection is not available in the browser. Neither stand-in is used on iOS or Android.

Steps 4 to 6 call a custom native module, so they do not run in Expo Go. Create a development build:

```bash
npx expo run:ios
npx expo run:android
```

`ios/` and `android/` are generated by prebuild and are gitignored.

Biometrics on a simulator:

- iOS: Features → Face ID → Enrolled, then Matching Face or Non-matching Face when the prompt appears. If Face ID is not enrolled, the payout stops and asks the merchant to set it up in Settings.
- Android: Settings → Security → Fingerprint, then the emulator extended controls to simulate a touch.

Screenshots:

- iOS: Device → Trigger Screenshot. Command-S does not post `userDidTakeScreenshotNotification`.
- Android 14+: `adb shell input keyevent 120`. `ScreenCaptureCallback` only hears the hardware keys, and it does not exist before API 34, so older Android devices do not show the warning.

The mock API waits 0.5–2 seconds on a device so the loading states are visible. Tests skip that wait.

## Architecture

```text
app/                         Expo Router. Routes only wire navigation.
components/                  Screens and the shared button, field, and amount text.
hooks/                       TanStack Query hooks and the screenshot subscription.
lib/money, iban, date        Pure rules. No React, no fetch.
lib/api                      fetch, Zod parsing, and error mapping.
lib/security                 Decides when a payout may call the API.
modules/screen-security      Expo native module. Swift and Kotlin.
mocks/                       The provided MSW handlers.
```

Server state lives in TanStack Query. The payout form is local state: the phase is `editing`, `review`, `submitting`, `success`, or `failure`. Query retries are for reads. A payout POST is never retried automatically.

The native module is named `ScreenSecurity` and exposes three things:

- `getDeviceId()` returns `identifierForVendor` on iOS and `ANDROID_ID` on Android.
- `isBiometricAuthenticated()` is an async function. It resolves `true` or `false`. It rejects `BIOMETRICS_NOT_ENROLLED` or `BIOMETRICS_UNAVAILABLE` when there is nothing to prompt.
- `onScreenshotTaken` is emitted from `UIApplication.userDidTakeScreenshotNotification` and, on API 34+, `Activity.ScreenCaptureCallback`.

`authorisePayout` sits between the screen and that module. Amounts of 100,000 minor units or less skip the prompt and still attach `device_id`. Amounts above that wait for the prompt and do not call `/api/payouts` if it fails.

## Design decisions

**Money stays in integers.** The API uses minor units. The amount field is parsed with integer arithmetic, so `0.29` becomes 29 and never a binary float that rounds the wrong way. More than two decimal places is rejected rather than rounded. A negative amount is a distinct state so the button stays disabled and the field can explain why. Empty and zero also disable Confirm.

**The biometric line is “over 1,000.00”.** 1,000.00 does not prompt. 1,000.01 does. GBP and EUR use the same numeric line. The brief says “or equivalent”, and there is no FX rate, so €1,000.00 is treated as the equivalent of £1,000.00. The payout currency is allowed to differ from the account currency, and the client does not guess whether the merchant can afford it. The mock only returns insufficient funds for 88,888 minor units.

**IBAN checks are the ISO 13616 mod-97 check**, plus the registered length for countries we know. `GB29NWBK60161331926819` passes, including spaces and lowercase. The long FR sample fails. The confirmation sheet masks everything except the first and last four characters. The value sent to the API is the compact uppercase form.

**Dates are `DD MM YYYY` in the device timezone**, for example `23 01 2026`. The reference screenshots render `23 Jan 2026`. The written requirement is the token `DD MM YYYY`, so that is what the list uses. It is a one-function change if the abbreviated month is preferred.

**A 201 can still be a failed payout.** The mock completes most amounts, returns 400 for 888.88, returns 503 for 999.99, and returns 201 with `status: "failed"` when the minor amount ends in 99. The client treats that last case as a failure instead of showing a success tick.

**Biometrics are the platform APIs, not a third-party SDK.** iOS uses `LAContext` with `deviceOwnerAuthenticationWithBiometrics`, and the passcode fallback button is hidden. Android uses `androidx.biometric` with `BIOMETRIC_STRONG`, back to the Expo minimum SDK. The boolean contract cannot tell a cancel from a mismatch, so both use the reference copy “Biometric authentication was cancelled.” Not enrolled is a rejection, which is what lets the screen tell the merchant to open Settings.

**A missing device id does not block a small payout.** The request still sends `device_id`, using `unknown-device` if the bridge throws. A large payout still stops if biometrics cannot run.

**The home preview and the modal are different reads.** Home calls `GET /api/merchant` and shows the three newest rows after sorting by date. The modal calls `GET /api/merchant/activity` and follows `next_cursor`. A failed next page keeps the rows already on screen and offers a retry. Show More stays available when the preview is empty, because the ledger endpoint can still have rows.

## Assumptions

- Minor-unit amounts from the API are integers. Zod rejects anything else.
- “Over £1,000.00” is exclusive of 1,000.00, in the currency selected on the form.
- The server, not the form, decides insufficient funds. A GBP balance cannot be compared with a EUR payout without a rate.
- `identifierForVendor` and `ANDROID_ID` are acceptable device identifiers for this exercise. Both can change on reinstall or factory reset.
- Screenshot protection is a warning, not `FLAG_SECURE`. The brief asks for an event and a reminder.
- Android screenshot detection is only required from API 34.

## With more time

- Send an idempotency key on `POST /api/payouts` and keep the receipt locally.
- Quote an FX rate when the payout currency differs from the account, and warn before confirm.
- Share one activity feed between the home preview and the modal so the two cannot disagree.
- Add a Maestro or Detox pass on a simulator for the biometric and screenshot prompts. The Jest suite mocks the bridge, which is the right unit boundary, and it does not prove the Swift or Kotlin.
- Hide payout details from the app switcher as well as warning on screenshot.
- Replace the resettable device id with an attested installation id if this were a real payout rail.

## Walkthrough

A suggested shape for 60 minutes:

1. **The flow, on a simulator or the web preview (about 5 minutes).** Home balances, three activity rows, Show More, then a £400 payout through confirm and success. Point at the disabled Confirm button with `0` and with the invalid FR IBAN.
2. **Money and the IBAN (about 10 minutes).** Open `lib/money.ts` and show `0.29 → 29`, the rejection of a third decimal, and the `>` comparison at 100,000 minor units. Open `lib/iban.ts` for mod-97 and the two sample IBANs. Mention the screenshot date format and why the code follows the written token.
3. **The payout phase machine (about 10 minutes).** `components/payout/payout-screen.tsx`: review, then `authorisePayout`, then `createPayout`. Why the POST is not retried. How 888.88, 999.99, a `.99` amount, and a dropped network become four different messages on the same failure screen.
4. **The native module (about 10 minutes).** `ScreenSecurityModule.swift` and `ScreenSecurityModule.kt`. Sync device id, async biometrics, and the screenshot event. Why “not enrolled” is a rejection and “cancelled” is `false`. API 34 as the Android screenshot floor.
5. **Tests (about 10 minutes).** Domain tests do not render. `payouts.test.ts` hits the real MSW handlers, including both error triggers. The screen tests drive the button states, the masked confirmation, the device id on the request, and the biometric gate. The bridge is mocked at `screen-security`, so the policy is tested without a simulator.
6. **What I would change (about 10 minutes).** Idempotency, FX, one activity source, and an end-to-end run of the native prompts. Leave the rest for questions.

## Requirement map

| Requirement | Where it is handled |
| --- | --- |
| Available and pending balance with the currency symbol | `BalanceSummary`, fed by `GET /api/merchant` |
| Three most recent activity rows, description and amount only | `HomeScreen` via `mostRecentActivity` |
| Show More opens the full list | Home button pushes `/modal` |
| Home loading and error, with retry | `HomeScreen` |
| Activity rows show type, description, amount, and `DD MM YYYY` | `ActivityListItem`, `formatActivityDate` |
| Infinite scroll with cursor pagination | `useActivityFeed` and `FlatList.onEndReached` |
| Modal loading and error, including a failed next page | `ActivityModal` |
| Numeric amount, GBP or EUR, IBAN | `PayoutScreen` |
| Valid and invalid IBAN samples | `isValidIban` |
| Form stays usable with the keyboard open | `KeyboardAvoidingView` and `keyboardShouldPersistTaps` |
| Confirm disabled for empty, zero, or negative | `interpretAmountInput` drives the button |
| Confirmation before the payout is sent | `ConfirmDialog` |
| Success shows amount and currency | `PayoutResult` |
| 4xx, 5xx, insufficient funds, network, and a failed payout status | `mapHttpError`, `createPayout` |
| `ScreenSecurity.getDeviceId()` sent as `device_id` | Native module and `createPayout` |
| `isBiometricAuthenticated()` over 1,000.00, abort on false | `authorisePayout` |
| Not enrolled tells the merchant to open Settings and aborts | Native rejection mapped in `authorisePayout` |
| `onScreenshotTaken` on the payout screen | Native events and `useScreenshotWarning` |
